## Implemented behavior

`statedCircuitAuthority.ts` now computes exact source subtree resistances alongside its netlist solution. Dependency identities uniquely bind intermediates (including transitive resistor dependencies), rather than matching a claimed scalar or source marker. The actual `Rs=6` survives; valid `Req`/`Itot` links and all three qualitative-claim links survive. Duplicate IDs, dangling references and cycles are withdrawn transitively, and claims referencing withdrawn quantities are removed.

The optional `{ requireBoundClaims: true }` policy rejects unbound coincident scalars and source-role conflicts, checks resistance dependency coverage, and does not treat a leaf resistance as the whole equivalent merely because their values coincide. The default keeps the inherited unbound-value behavior for existing callers; **the parent must select strict mode after a successful full-IR bind**. This is an explicit integration requirement, not a claim that strict mode already runs in the app. Final solver projection/audit refresh remains mandatory.

`readStatedCircuitProblemSource(question)` uses the existing detector/generator with no plan and exact netlist math, without calling the compiler. It returns an uncommitted source candidate. The new binder and strict authority use this path, avoiding recursion when the parent installs a compiler guard. Existing `solveStatedResistorCircuit` keeps its compiled legacy path for existing callers.

`bindStatedCircuitProblem(question, problemIR)` binds every carried item:

- Physical resistor/cell/ammeter/voltmeter entities retain full source labels on real circuit symbols. Quantities and visible value annotations independently carry resistor values and cell voltage, including actual `eV=5` and its cell owner.
- Actual tree combination entities bind to genuine source subtrees. Their member IDs, visible enclosure targets and computed labels are source-derived; they are not substitute physical bodies.
- Given literal expressions bind to their source quantity, unit and physical owner. Requested expression ASTs must match the canonical source-tree formula (allowing associative/commutative sums/products), not just evaluate to the same result. For example `(2+4)/3=2` is rejected as equivalent-resistance authority for `(2+4)||3`.
- All facts, requested clauses, expressions and entities are accounted for. Unsupported extra components, quantities, assumptions, constraints or requests decline; full IR is never reduced and obligations are never exempted.

`checkStatedCircuitProblemBinding(question, problemIR, document)` reconstructs from the independent whole question/full IR and returns fatal `circuit_problem_binding` issues on identity, topology, quantity/unit, label, requirement or reveal disagreement. Source and provenance fields grant no authority. Object keys are canonicalized for JSONB; array/reveal order remains checked. The comparison deliberately requires the source-built layout until a separate topology correspondence is proved.
